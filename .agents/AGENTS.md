# Project Rules

## Git Push Permission Rule
- **CRITICAL**: Before executing any `git push` command to GitHub or remote repositories, ALWAYS obtain explicit approval from the USER first.
- Do NOT perform automatic `git push` without asking the user.

## 개발일지 작성 규칙 (Development Log Guidelines)
- **시간대별 구성**: 상세 개발 이력 작성 시 시간대(예: `[10:30]`, `[14:00]`, `[23:50]`)를 명시하여 타임라인 순으로 기록합니다.
- **간결한 요약**: 지나치게 장황하고 긴 기술 명세는 지양하고, 핵심 작업 내용과 결과를 조금 간단하고 직관적인 불릿 포인트로 작성합니다.

## 작업 완료 후 수정 파일 및 라인 안내 규칙 (Modified Files & Lines Notification)
- 개발 작업 완료 후 최종 응답 시, **어떤 파일이 수정되었는지와 해당 파일의 몇 번 줄이 수정되었는지(줄 번호 범위 포함)**를 반드시 함께 안내합니다.
  - 예시: `[page.tsx](file:///...) (라인 126~155)`
